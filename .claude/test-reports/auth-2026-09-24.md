## Coverage

**`src/lib/http.ts`:** request interceptor attaches `Authorization: Bearer <token>` from
the shared `queryClient`'s session, omits it when signed out; response interceptor's
401-refresh-retry flow (deduped concurrent refreshes, retry once, hard redirect to
`/sign-in` on refresh failure); auth endpoints excluded from the retry loop;
`getApiErrorMessage`/`getApiFieldErrors` normalization.

**`src/features/auth/api/auth.ts`:** exact request bodies (hardcoded `role: "customer"`),
`signIn`'s hardcoded "Invalid email or password" on any 401, `refreshSession` never
throwing, `logout` pass-through.

**Hooks:** `useSession` (query key, bootstrap-only refetch via `staleTime: Infinity`),
`useSignIn` (cache write on success, 401 error message), `useSignUp` (no auto-login, 400
field errors, 409 message), `useLogout` (`onSettled` clears session + navigates to
`/sign-in` on both success and network failure).

**Components:**
- `SignInForm` — customer → `/`, admin → `/admin` redirect, 401 error text,
  disabled+spinner while pending
- `SignUpForm` — success toast + redirect to `/sign-in`, client-side password-mismatch
  message, 400 field-error mapping, 409 message, disabled+spinner
- `NavBar` — signed-out/customer/admin states, Admin link only for `role === "admin"`
- `RequireAuth` (**protected-route behavior**) — loading spinner, redirect to
  `/sign-in` when unauthenticated, renders children when authenticated, role-matching
  pass-through, wrong-role redirect to `/`
